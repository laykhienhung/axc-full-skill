# ProtoFlow — the project brief (`docs/interview.html` + `docs/interview-tree.html`)

The project brief is two pages over the same data — `docs/interview.html` (**Tabs** view) and `docs/interview-tree.html` (**Tree** view) — linked to each other from their top bar. It shows what the BA said in the domain interview, what it is based on, and — once materials are grounded — whether each point held up. It is **derived** (see [truth-vs-derived.md](truth-vs-derived.md)) from `docs/_global/interview.md` and `docs/_global/grounding.md`, and regenerated by both `/protoflow-interview` and `/protoflow-ground`. Never hand-edit it.

## Rendering

Build `const BRIEF = { … };` once from the whole `interview.md`, then write both pages:

| Template | Page |
|----------|------|
| `<pack>/references/templates/interview.html` | `protoflow/<project>/docs/interview.html` |
| `<pack>/references/templates/interview-tree.html` | `protoflow/<project>/docs/interview-tree.html` |

Copy each template, replacing **only** the contents of `<script id="brief"> … </script>` with the same `BRIEF`. Always write both — never one without the other, or the view links break. Touch nothing else — fix view bugs in the templates, not the copies. Escape any `</script` inside strings as `<\/script`. Skip the render when `interview.md` holds only template placeholders.

- **Tabs** (`interview.html`, the default page): Overview · People & today · Scope & rules · Words & data · To ask — one tab shown at a time; print lays out every tab.
- **Tree** (`interview-tree.html`): the same branches as a fold-out outline, with "Only what needs checking", Expand all / Collapse all.

Only uncertain or checked points carry a flag (guess, unknown, matches / disagrees with materials). Both pages read the same `BRIEF` — no extra fields.

## `BRIEF` shape

One array per section; `rejected` items are left out. Each item carries `label`, `type`, `text`, `check` (below). Keep `text` to one or two plain sentences — the brief is for a quick read; the doc holds the detail.

| Key | From `interview.md` | Extra fields |
|-----|---------------------|--------------|
| `project`, `generated` | project id, today | |
| `basis` | `## Source basis`, plus a count of `materials/` files (ignore `.gitkeep`) and the last `/protoflow-ground` run (latest date in grounding's Materials index notes, or blank) | `{ materials: "none"\|"expected"\|"available", files: N, groundedAt: "<date>" or "" }` |
| `sessions` | `## Sessions` rows | `date`, `ba`, `topics` |
| `glance` | `## Domain at a glance` prose (string) | |
| `actors` | `## Stakeholders & actors` | `role` — uses / decides / affected (short) |
| `process` | `## Current process (as-is)`, in order | `actor`, `tool` |
| `pains` | `## Pain points` | |
| `goals` | `## Goals & success measures` | `measure` (omit if none) |
| `scope` | `## Scope boundaries` | `kind`: `in` / `out` / `unsure` |
| `rules` | `## Business rules & limits` | |
| `volumes` | `## Volumes & frequency` | |
| `outputs` | `## Outputs & notifications` | |
| `systems` | `## Existing systems & screens` | `fate`: `replace` / `keep` / `integrate` (omit if unknown) |
| `terms` | `## Key terms` rows | `term`, `meaning`, `type`, `check` (no `label`/`text`) |
| `data` | `## Key data` | |
| `constraints` | `## Constraints` | `kind` — e.g. regulation, integration, deadline |
| `risks` | `## Risks & sensitivities` | |
| `questions` | `## Open questions` (not `rejected`) | `label`, `text`, `check` |
| `materials` | `## Materials to expect` rows | `name`, `contains`, `lookFor`, `received` (`yes`/`no`/`expected`) |

## `check` — did the materials back it up?

The link between an interview point and the materials is written by `/protoflow-ground` into `grounding.md` as `BA interview › <label>` (the interview item's `### <label>`, or the term for a Key-terms row). Derive each item's `check`:

| `check` | When |
|---------|------|
| `interview-only` | `basis.materials` is `none` |
| `contradicted` | a non-rejected `CONFLICT` in `grounding.md` has `Source:` containing `BA interview › <label>` |
| `matched` | a grounding item's `Source:` contains `matches BA interview › <label>`; for an open question, a grounding `FACT` whose `Source:` contains `answers BA interview › <label>` |
| `unchecked` | otherwise (materials expected, or read but silent on this point) |

`contradicted` wins over `matched` when both hold.
